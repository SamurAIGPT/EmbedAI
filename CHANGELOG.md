# Changelog

## Unreleased

## v0.2.0 (2026-10-22)

### Changed
- **Renamed to Open Duet.** The product name shown in the app, the desktop messages, the installers' file names, the README and the docs is now Open Duet. Names that identify an install did not change, so nothing needs migrating: the `OPEN_DOTS_*` settings, the `~/.open-dots` data folder, the desktop data folder (still `Open Dots`, which also keeps its encryption key readable), the `opendots` service account, the `open-dots.service` unit, Docker image and volume names, and the `X-Open-Dots-Token` header.
- The repository moved to `Anil-matcha/open-duet`; the old address redirects. Clone commands in the README and the self-hosting guide use the new name.
- **Engine processes get an allow-listed environment.** Claude, Codex and ACP engine processes (and the shell commands and tool servers they start) used to inherit the server's whole environment minus five names. They now get standard shell, OS, proxy and certificate names plus the engines' own settings and provider keys; anything else is dropped. `OPEN_DOTS_ENGINE_ENV` adds names or `PREFIX*` patterns; the app's own secrets, database settings and `OPEN_DOTS_*` names can never be added.
- **The web UI and API now require sign-in (owner authentication).** Every request outside the desktop app must come from the owner signed in with a passphrase (a session cookie), from a device paired with a one-time code (a bearer token), or, only if you enable `LOOPBACK_TRUST`, from this machine. On first start the page asks you to set the owner passphrase, which works only from the server itself; on a remote server run `uv run python -m app.auth.cli set-passphrase` in `backend/`. Scripts that called the API from this machine without a token now get `401` unless you pair them (`python -m app.auth.cli pairing-code`, then `POST /api/v1/auth/pair`) or set `LOOPBACK_TRUST=programs` (read the tradeoff in [docs/AUTH.md](docs/AUTH.md#loopback-trust)). Requests whose `Host` is not in the new `TRUSTED_HOSTS` (default `localhost,127.0.0.1,[::1]`) are refused with `421`; add your public name when self-hosting. The browser no longer decides who it is: the guest or Telegram id the web UI kept in `localStorage` moves to the server on the first sign-in and is then read from the session. The desktop app is unchanged. Run `alembic upgrade head` (it adds three tables).
- Claude runs started by the app no longer let the CLI save its own memory notes under `~/.claude/projects/` (outside the workspace, without an approval card). The app sets `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` for the processes it starts; your own use of the CLI is unchanged.
- The backend now checks every 15 seconds for conversation turns (see "Durable local conversations" below) whose process stopped, and interrupts the turns it is running when it shuts down cleanly. It does nothing unless threads are used.
- Boat is now an optional provider. `BOAT_API_KEY`, `HOOK_TOKEN` and `PERMISSION_HOOK_BASE_URL` are no longer required to start the backend; `scripts/dev.sh` only requires the hook settings when a Boat key is set. Work that needs a Boat sandbox answers 503 "Boat is not configured" when the key is empty, and the permission hook endpoint rejects every request when `HOOK_TOKEN` is empty. Existing setups with a key are unchanged. Without a Boat key the app is chat-only unless you enable local tools (below): local Claude answers questions but cannot use schedules, Telegram tasks or GitHub push, so keep Boat configured if you need those.

### Fixed
- Returning to an engine with a native session after a fallback turn now supplies the missing exchanges as historical background from the durable transcript. The handoff survives backend restarts, includes partial fallback output, and clears after a successful original-engine turn or an explicit session reset.
- A fallback engine that replays conversation history now uses its own context budget and token estimate, including when the original engine keeps a native session and does not compact replayed history.
- Page titles say Open Dots instead of the old product name.
- **SIGTERM no longer hangs the backend while the web page is open.** The server waited for every open connection before shutting down, and an event stream never closes by itself, so a stopped backend kept waiting with its turns still running. Event streams now end as soon as a stop signal arrives; shutdown stops the background jobs first, refuses new turns, kills each running turn's engine process group and marks the turn interrupted, and settles routine runs that followed those turns as interrupted with their notification (they used to stay running until the next start). Tested with real signals on the real backend process. See [docs/RELIABILITY.md](docs/RELIABILITY.md).
- Starting a turn no longer hangs when an engine's status check hangs, or answers 500 when it raises: the check is bounded (45 seconds) and a broken engine is reported as unavailable (503 with the reason).
- The PostgreSQL schema-equivalence test no longer reports the `computer` table as different: PostgreSQL turns a quoted integer default (`'1000'`) into a bare `1000` and SQLite keeps the quotes; both now count as the same default.
- Security: a newline (or a single `&`, `||`, a subshell, `$(...)` or backticks) no longer hides a risky command behind a harmless one. The git risk classifier used by the sandbox permission hook only split on `&&`, `;` and `|`, so `git status` followed by a newline and `git push` was classified as a read and a saved "always allow" for `git status` approved the push (issue #157). It now splits on every shell separator, finds `git` anywhere in each part (including `sudo git`, `env X=1 git`, `bash -c '...'`), and classifies by the riskiest verb. The local safety floor had the same flaw: `echo hi`, newline, `rm -rf ~` read as one harmless command. A newline now starts a new command there too. Newlines inside quotes are unchanged.
- On SQLite, a deleted conversation's id is no longer given to the next new conversation (delete conversation 4 and the next one used to be 4 again), so a saved `/chat?thread=N` link, the decision log's conversation filter and the sentinel's scan no longer end up pointing at a different conversation. The same holds for turn and event ids. Run `alembic upgrade head` (`scripts/dev.sh` and the desktop app do): revision `8d5f3a2b6c74` rebuilds the `thread`, `turn`, `event` and `approval` tables as `AUTOINCREMENT` in one transaction, keeping every row, id, index and foreign key, and starts new conversation ids above any id the decision log still names. The desktop app copies the database aside first, as for every update. PostgreSQL never reused ids; its schema is unchanged and the migration does nothing there. Tested on SQLite and PostgreSQL. See [docs/SETUP.md](docs/SETUP.md#database).
- docs/SETUP.md no longer says an agent's new instructions and notes apply to its next message in a conversation already started: the Claude CLI keeps a resumed session's system prompt (checked with Claude Code 2.1.302), so they reach conversations started after the change; model and approval mode do apply to the next message. It also says that **Plan only** still lets the CLI save its plan file in `~/.claude/plans`.
- The Approvals panel's **Add a rule** form no longer squeezes the command box to a sliver beside a full-width "Exactly / Starts with" menu; the Decisions and Health filters get the widths they ask for too.
- On SQLite, **Always allow this command** no longer fails with "database is locked" and answers "allowed this once only". Saving (and removing) a rule now takes the write lock before it reads, instead of upgrading a read whose snapshot went stale while the turn the answer had just woken up was writing its events.
- The PostgreSQL schema-equivalence test no longer reports the `agent` table as different: PostgreSQL reports string defaults with a cast (`'ask'::character varying`) and SQLite reports boolean defaults as `1`/`0`; both are now treated as the same default. The agent table and `thread.agent_id` have their own equivalence check.
- The page no longer dead-ends when Claude is not connected in a Boat sandbox. Task history is always readable and expandable (only sending new tasks and replies needs Claude connected; with Boat off the new-task and reply boxes are hidden), and GitHub can be connected as soon as the sandbox exists instead of waiting for the Claude login. With Boat off (`BOAT_API_KEY` empty) the Connect Claude, GitHub and submit steps are replaced by a short explanation, and the history stays visible. New `GET /api/v1/providers` reports whether Boat is on (never a key or URL); an older backend without it is treated as Boat on.

### Added

- **OpenRouter engine preset** (see [docs/ENGINES.md](docs/ENGINES.md#openrouter)): a new `openrouter` engine on top of the OpenAI-compatible one, with its own encrypted configuration so it can sit beside a local endpoint. Only an API key is needed (the address defaults to `https://openrouter.ai/api/v1`); model ids are OpenRouter's (`openai/gpt-4o-mini`); requests to openrouter.ai carry OpenRouter's optional `HTTP-Referer`/`X-Title` app-attribution headers (used for its public app rankings; never sent to another address). Settings → Engines shows it. Chat only. Tested against a mock endpoint, not the real service.
- Workspace files (F08): download a folder, or the whole workspace, as a zip. `GET /api/v1/threads/{id}/files/zip?path=` (admin scope, like the rest of the file browser) applies the same confinement to every file it adds: secret files and folders, links out of the workspace, special files and names unsafe inside a zip (backslashes, drive prefixes, control or bidi characters, invalid UTF-8; counted in `X-Skipped-Unsafe-Names`) are left out, folder links are not followed, each file is opened with `O_NOFOLLOW` and an inode re-check. At most 2000 files and 200 MB before compression (`413 too_large` otherwise); the temporary zip is deleted after it is sent. A **Download zip** button in the Files panel. See [docs/EVERYDAY.md](docs/EVERYDAY.md#workspace-files).
- Routines can retry a failed run (see [docs/ROUTINES.md](docs/ROUTINES.md#retries)). `retry_limit` (0 to 3, default 0, off) and `retry_delay_minutes` (1 to 1440, default 5) are set per routine, in the API, in export/import and under "Limits and approvals" in the editor. A failed run (an engine failure, or a start that failed because the engine was unavailable, the workspace was not usable or an unexpected error occurred) is queued again as a new run with trigger `retry`, its `attempt` and the `retry_of` run it repeats. A completed, stopped, run-limited or interrupted run, and a start that failed for a configuration reason (agent gone, archived or unavailable, unknown engine, invalid model, local execution off), is never retried. A scheduled occurrence that falls due replaces a waiting retry, and a retry still queued at a restart and past the catch-up window is recorded as missed. A unique index on `routine_run.retry_of` keeps a failed run to one retry, and the usual conditional claim keeps it to one start. Run `alembic upgrade head`: revision `c8d2e5a9f314` adds the four columns and the index (no table rebuild).

- Self-hosting on a server you own (experimental, one owner; see [docs/SELF-HOSTING.md](docs/SELF-HOSTING.md), which lists what was run and what was not). `python -m app.server` runs the backend and the exported web pages in one process (`OPEN_DOTS_HOST`, `OPEN_DOTS_PORT`, `OPEN_DOTS_UI_DIR`); the pages are public so `/login` and `/pair` can load, while the API, `/hooks/*` and `/docs` keep their sign-in rules. It listens on loopback and refuses any other address unless `OPEN_DOTS_ALLOW_PUBLIC_BIND=1` is set. Commands: `migrate` creates or updates the database first (a SQLite file is copied aside before a pending change; a file this app did not make or a wrong encryption key is refused untouched, and the server will not start on a database that is not ready), `doctor` checks the machine and changes nothing, `backup` and `restore` make and unpack one archive of the database, attachments, decision log, notes and workspace (not the encryption key or the engines' sign-ins), and `service` writes a systemd unit. A Docker image and `compose.yaml` run it in a container with its data in a volume, and `deploy/proxy/` holds nginx and Caddy overlays with TLS. `TRUSTED_PROXIES` names the addresses (besides loopback) whose `X-Forwarded-For` and `X-Forwarded-Proto` are believed; nothing else is, a network-wide or `*` entry is refused, and `FORWARDED_ALLOW_IPS` is ignored. `OPEN_DOTS_PUBLIC_URL` is one setting for the address people use: its host name is trusted and the pairing command prints a full link. The log warns once when a visit to the public name arrives without `X-Forwarded-For` or `X-Forwarded-Proto` from the reverse proxy. Engine programs installed in the service account's home are found under a service. `node scripts/build-ui.js` builds the pages for the desktop app and for a server alike. The Routines panel now shows a full webhook address when the page is served by the backend itself. Not run on a real server: see the guide.

- Reliability and limits (see [docs/RELIABILITY.md](docs/RELIABILITY.md) and [docs/ENGINES.md](docs/ENGINES.md#limits-and-the-fallback-engine)). **One routine scheduler per PostgreSQL database:** the backend holding a session-level advisory lock runs it; others stand by, queue Run now and webhook runs for it, and take over within one pass after it stops (clean stop or `kill -9`); startup recovery on PostgreSQL leaves runs whose turn still heartbeats alone. **Orphan sweep:** engine process groups are recorded in `ENGINE_PROCESS_DIR` with start time, program and owner, and engines carry an environment marker; the next start kills what a crashed backend left (a recycled pid, a live backend's engines and a cleanly stopped backend's background processes are never touched). **Replay classification:** turns record `engine_phase`; `turn.interrupted` carries `replay` (`before_accept`, `unknown`, `after_accept`) and the page says whether the engine had the message; nothing is re-run. **Limits:** usage/rate limits and lack of credits reported by Claude (including its `rate_limit_event` reset time), Codex and OpenAI-compatible endpoints become `engine_limited`; `GET /engines` returns `limit` and the picker shows a "resets in" chip. **Fallback engine:** agents take `fallback_provider`/`fallback_model`; a turn the engine refused before accepting it moves to the fallback only when the fallback covers tools, approvals, images, the agent computer and a continuing conversation's earlier messages and is ready, with an `engine.switched` notice in the transcript; otherwise the turn fails with the reason and next step. Run `alembic upgrade head`: revision `f3b8d1e6a274` adds `agent.fallback_provider`, `agent.fallback_model` and `turn.engine_phase` (nullable, no table rebuild). Tested on SQLite and PostgreSQL 14 (schema equivalence, migration round trip), two real backends on PostgreSQL, real processes for the sweep, and live with Claude CLI 2.1.302 on haiku behind a fake 429 endpoint.

- Memory depth and context management (see [docs/MEMORY.md](docs/MEMORY.md)). **Topic notes:** besides `MEMORY.md`, each agent keeps `memory/<topic>.md` notes (front matter `title`/`aliases` optional); the system prompt lists them as an index (at most 40 topics / 2,000 characters), never their bodies. Same safety as `MEMORY.md`: secrets redacted on save and on every load, atomic `0600` writes, 64 KB per note and 100 notes per agent, a hash check that refuses a save over a change made meanwhile (`409 memory_changed`), links never followed. `GET/PUT/DELETE /api/v1/agents/{id}/memory/topics[/{name}]` and a **Topic notes** tab under the agent's notes in the Agents panel. **Recall before each turn:** the person's message is matched (any content word; two needed for a message of five or more) against the agent's topic notes and its other conversations with a portable OR query on SQLite and PostgreSQL; up to 4 note and 4 conversation passages, at most 6,000 characters, go in front of the message (never the system prompt, so prompt caching stays stable) inside a block that says they are background found automatically and grant no permission; stored as a `memory.recalled` event and shown as a **Recalled** chip that opens to show every passage. Per-agent `recall_enabled` (on by default; off with notes off). **Context compaction** for engines that replay the transcript (OpenAI-compatible endpoints, and ACP agents that cannot reload their session): when the estimated replay (per-engine characters-per-token) reaches the budget (24,000 tokens, or 80% of a new optional `context_tokens` on the endpoint's config), everything before the last 4 exchanges is folded into a deterministic excerpt summary (no model call), stored as a `context.compacted` event so later turns replay the same summary, and the transcript shows **Earlier messages summarized** with the summary behind a button. Claude and Codex keep using their CLI's own compaction. **Journal with undo:** every change made through the app to an agent's notes is recorded outside the agent's folder with a diff and the earlier text; **History** shows it and **Undo** puts a file back (an undo can be undone). **Proposed notes:** once a conversation has been quiet for two minutes, lasting statements in the person's own words ("remember that…", "I prefer…") are queued as proposals; nothing is written until you **Accept** (journaled) or **Reject** (never proposed again). The OpenAI-compatible engine now receives the turn's prompt for the current message (so attached text files and recalled passages reach it). Run `alembic upgrade head`: revision `e7a91c4d2b58` adds `agent.recall_enabled`. Tested on SQLite and PostgreSQL 14 (full suites and schema equivalence), and live (see docs/MEMORY.md).

- Everyday features (see [docs/EVERYDAY.md](docs/EVERYDAY.md)). **Search:** `GET /api/v1/search?q=` over conversation titles, what you wrote and what the agent answered; every word must appear in one title or message (case-insensitive, wildcards literal), newest first, with a ~160-character snippet and `[start, length]` highlights; filters `agent_id`, `since`/`until`, `include_archived`, `limit`. - Reliability (see [docs/RELIABILITY.md](docs/RELIABILITY.md)): **one backend per SQLite database**, through an operating-system lock next to the database file that ends with its process (a crash leaves no stale lock); a second server or desktop launch on the same data refuses to start and names the process that holds it. **Turn watchdog:** a turn whose engine does nothing for `TURN_STALL_SECONDS` (default 600, `0` off) while not waiting on an approval is stopped and fails with `engine_stalled`. **Tests that run the real backend process** (`backend/tests/e2e/`): shutdown with real signals, engine resilience with hanging and crashing engine programs, and features checked together under the real auth middleware (a routine on an agent with a computer waiting for an approval, the webhook ingress against the main app, chat-scope devices, approvals and the decision log on Claude, Codex and ACP). **`scripts/smoke-backend.py`**, a first-day end-to-end run (passphrase, sign-in, agent turn, approval, routine, second backend refused, SIGTERM, restart) with a fake `claude`, now a CI job.

- Routines: local agents on a schedule, by webhook, or by hand, without Boat (see [docs/ROUTINES.md](docs/ROUTINES.md)). A routine runs a prompt as a new conversation of one named agent, through the same thread runtime and approval gate as a chat (the agent's engine, model, instructions, workspace and computer). Schedule kinds: cron (Sunday = 0, either-day-field semantics), chosen weekdays at a time, every N minutes (elapsed, from an anchor), once, and manual; IANA timezones; a spring-forward gap fires after the gap and a repeated autumn hour fires once; the editor shows a plain-language summary and the next three dates from the same code the scheduler uses (`POST /api/v1/routines/preview`). The scheduler is a 5-second background loop in the backend: a due occurrence later than its catch-up window (default 60 minutes, plus 2 minutes of slack) is recorded as `missed`; a backlog runs its newest occurrence once and records the rest as one missed run; an occurrence while the previous run is still working is `skipped`, never overlapped. **Unattended runs never approve by themselves:** a run uses the stricter of the routine's and the agent's approval mode, a request parks the run in `needs_input` with a notification, and nobody answering within the routine's approval wait (default 30 minutes) expires the request, which the engine receives as a denial; saved rules and the safety floor apply as in a chat. A run limit (default 30 minutes) counts active time only. **Restart recovery:** a run is marked running before its conversation is created, and at startup any run left running or waiting becomes `interrupted` and is never re-run. Run history (`queued`, `running`, `needs_input`, `completed`, `failed`, `missed`, `skipped`, `interrupted`) links each run to its conversation. **Webhooks:** `POST /hooks/{id}` with a bearer secret that is shown once, stored only as a SHA-256 hash and rotatable; checked before the body is read; bodies over `ROUTINE_WEBHOOK_MAX_BYTES` (64 KiB) are 413, non-UTF-8 415, a paused routine 409, more than 3 unfinished webhook runs 429; the body reaches the agent inside a delimited, escaped block marked as untrusted data. `app/ingress.py` is a separate app that serves only `GET /health` and `POST /hooks/{id}`, for exposing webhooks through a tunnel. **Notifications:** an in-app feed (`/api/v1/notifications`, unread count, mark read) for runs that need input, failed, were missed or interrupted, or completed, with a bell and unread badge in the Chat header, plus a copy to `ROUTINE_TELEGRAM_CHAT_ID` when it and `TELEGRAM_BOT_TOKEN` are set. Export leaves secrets out; import creates routines paused and without a webhook. The Chat page gets a Routines panel (create/edit with schedule picker and preview, run now, pause/resume, history with links to conversations, webhook URL and secret shown once, delete). `ThreadRuntime.send_turn` accepts a per-turn approval mode and approval timeout. The Boat schedules are unchanged. Run `alembic upgrade head`: revision `b5e3c8a1d702` adds the `routine`, `routine_run` and `notification` tables and changes nothing that exists. Tested on SQLite and PostgreSQL 14 (including schema equivalence), with time-travel tests for cron, timezones and DST, missed runs, overlap, approval parking and timeout, the run limit, recovery and webhook auth; verified live with the real Claude CLI 2.1.302 on a haiku agent (every-minute routine, webhook through the main app and through the ingress, approval parking that timed out to a denial, and a backend killed mid-run) and in the browser.
- Owner authentication and paired devices (see [docs/AUTH.md](docs/AUTH.md)). **Owner:** one passphrase per install, stored as a scrypt hash; set on first run from the server itself or with `python -m app.auth.cli set-passphrase` (which also replaces a forgotten one and signs browsers out). **Sessions:** `od_session` cookie, `HttpOnly`, `SameSite=Lax`, `Secure` over HTTPS (or behind a TLS proxy on the same machine), 30 days renewed on use up to 180; only SHA-256 digests of tokens are stored. **CSRF:** cookie-authenticated writes need `X-CSRF-Token`, derived from the session and handed to the page with it; sign-in routes accept JSON only. **Pairing:** **Settings → Devices** (or the CLI) opens an 8-character one-time code, valid 5 minutes, with a QR code of the pairing link (a small built-in encoder, no new dependency); the device's browser gets its own cookie, any other client a bearer token once. Codes are single use; 10 wrong codes from one address lock it out for 10 minutes, 10 wrong codes from anyone kill all open codes, and auth endpoints allow 30 requests a minute per address. Devices are `admin` (everything) or `chat` (conversations and approvals only; a default-deny route list). **Devices list:** every signed-in browser and paired device with scope, created and last seen, revocable at once. **Host/Origin:** `TRUSTED_HOSTS` allowlist against DNS rebinding, and an `Origin` must be the frontend's or the server's own. **Loopback trust:** `LOOPBACK_TRUST=off|programs|all` (default `off`); never applies when proxy headers are present. New endpoints: `GET /api/v1/health`, `GET /api/v1/auth/status`, `POST /api/v1/auth/setup|login|logout`, `GET /api/v1/auth/session`, `POST /api/v1/auth/pairing-codes`, `POST /api/v1/auth/pair`, `GET /api/v1/auth/devices`, `DELETE /api/v1/auth/devices/{id}`, `PUT/DELETE /api/v1/auth/identity`. Web UI: sign-in and first-run screens (`/login`), `/pair`, Devices and Sign out in Settings, redirects to sign-in when a session ends. Local execution now also accepts a signed-in or paired session (not only a browser on the machine). Tested on SQLite and PostgreSQL, and live against a running backend and the web UI.

- Agent computers (experimental). An agent can be given its own isolated Docker container (`POST /api/v1/agents/{id}/computer`, or **Computer** in the Agents panel), and its turns then run their commands and file edits there instead of on this machine: the host's own tools are off for those turns and the only tools are the computer's `exec`, `read_file`, `write_file` and `list_files`, served by a small MCP server bound to the container. Every call goes through the approval gate (cards, saved command rules matched like Bash, the safety floor, approval modes, the decision log); reads are allowed without a card, writes too in Accept edits, and Plan only refuses writes and commands. On Allow the app writes a one-use permit for exactly that call, and the MCP server refuses any call without one. The container runs as your own non-root user with no capabilities, no new privileges, no published ports, CPU/memory/process limits and only the agent's workspace folder mounted at `/workspace`; the network is off by default (or Docker's default bridge). The default image is `python:3.12-slim-bookworm`, pinned by digest; downloading an image is always an explicit step, never part of a turn. Lifecycle: start (makes the container from a local image), stop, recreate, live limit changes, idle stop after 30 minutes, a removal that is finished later if Docker is down, and removal of this installation's orphaned containers. A computer that cannot be used fails the turn with `computer_unavailable`; it never falls back to the host. `GET /api/v1/computers/health` reports whether Docker answers and never fails. Agents and conversations show their computer; the chat header has a Computer chip, and computer calls carry a "computer" badge. Run `alembic upgrade head`: it adds the `computer` table and changes nothing that exists. - Notes for named agents, starter notes, and an agent as one portable file. **Notes:** each agent keeps a Markdown file, `MEMORY.md`, in its own folder (`agents/<id>` under the workspace root, even when the agent works in a project folder). The start of it, at most 200 lines and then 24 KB, is added to every turn after the agent's instructions, marked as background that grants no permission, and the agent is told where the file is so it can keep it current (its edits ask for approval like any other). Anything that looks like a key, token, password or private key is replaced with `[redacted]` when the file is saved and again when it is loaded; the file is written atomically with owner-only permissions, and a link in its place is never followed. `GET /api/v1/agents/{id}/memory` returns the text, its `hash` and how much of it loads; `PUT` saves it, and with `expected_hash` refuses (409 `memory_changed`, with the current text) to overwrite a change the agent made meanwhile. - Approval modes, saved command rules, a safety floor and a decision log for local Claude turns (backend). **Modes** `ask` (the default and today's behaviour), `accept_edits` (the CLI lets file edits in the workspace through, everything else still asks) and `plan` (read-only) map onto the Claude CLI's own `--permission-mode`; an unknown mode is refused before the CLI starts, and chat-only runs stay locked down. There is deliberately no "full access" mode. **Always allow:** answering an approval with `{"decision": "allow", "remember": true}` saves that exact Bash command as a rule for that conversation's workspace folder; `GET/POST/DELETE /api/v1/approval-rules` list, add (exact or word-prefix match, optionally tied to a folder) and remove rules. A prefix rule never matches a command with shell operators (`;`, `&`, `|`, redirections, backticks, `$(`). Commands containing a credential, control characters or anything on the floor cannot be saved, and at most 200 rules are kept. A matching rule answers the question at once (the approval is still recorded and shown). **Safety floor:** a never-list of commands no rule can allow: recursive delete of `/`, the home folder or a system directory, recursive `chmod`/`chown` of the same, formatting or overwriting a disk device, force pushes, and fork bombs; a command that cannot be read to the end (unbalanced quote, `$(...)`, `eval`) is held too. Such a call is asked about on a card as usual. **Decision log:** every card shown, allow, deny, rule auto-allow, timeout and cancellation is appended, with secrets removed and the input cut to one summary line, to a monthly `decisions-YYYY-MM.ndjson` (mode 0600, in `~/.open-dots/decisions`, `DECISION_LOG_DIR`, or the desktop data folder; months older than `DECISION_LOG_RETENTION_DAYS`, default 180, are deleted). `GET /api/v1/decisions` reads it, newest first, with a `before` cursor and `event` and `thread_id` filters. All of it is local access only. No migration. See [docs/SETUP.md](docs/SETUP.md#approval-modes-saved-rules-and-the-decision-log).

- Stop, and managing conversations, in the Chat page and the threads API. **Stop** replaces Send while Claude is answering: Claude is stopped, what it had written so far is kept and marked unfinished, a question waiting for your Allow is cancelled (nothing runs), tool steps that had not finished are marked, and the conversation carries on with the same session. `POST /api/v1/threads/{id}/stop`. **Rename, archive and delete** are in each conversation's menu in the list: renaming keeps its place in the list, archiving hides it (and "Show archived" brings it back, with Unarchive), deleting asks first and removes the conversation's messages, tool calls and approvals from this app's database (not a secure erase: see docs/SETUP.md). - `python -m app.db.copy_to_sqlite`: copies an existing PostgreSQL database into a new SQLite file.
